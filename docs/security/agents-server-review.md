# Review: access control in the current agents server

**Private.** This page stays in this repository. It is not part of `docs/engine-integration/`, which moves public, and it must not be copied there or into any public issue. It lists the weaknesses in the engine's current access code that the zero-trust integration replaces. Their classes are the reason for the spec's [Security hardening](../spec/zero-trust-spec.md#security-hardening). The engine team uses this page to see which existing code its gateway retires, and the engine-side kit links to it as "read if you have access".

- **Reviewed:** `webgptorg/promptbook` at `54eb684a5` (2026-06-16), `apps/agents-server`. Paths below are relative to `apps/agents-server/src/`.
- **Method:** reading the code, with nothing run against a live engine. Each finding was checked against the file it names.
- **Scope:** sign-in, sessions, API tokens, cross-origin handling, unauthenticated routes, browser headers and dynamic code. Agent sandboxing, egress and the updater are out of scope; the spec covers them as Security hardening 2, 3 and 9.

Severity is for an engine that is reachable from the internet, as every tunnelled engine is: its hostname is public in Certificate Transparency logs within minutes.

## Findings

| #   | Severity | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                           | Where                                                                                                                                                   |
| --- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Critical | The session cookie's HMAC key is `ADMIN_PASSWORD`, or a fixed public string when that variable is unset. Anyone who knows the default, or the admin password, can mint a session for any user, admins included. The signature is compared with `!==`, which is not constant-time. Sessions are stateless, last two years, and cannot be revoked.                                                                                                  | `utils/session.ts` (the `SECRET_KEY` constant, the signature check, the cookie options)                                                                 |
| 2   | Critical | Several access decisions only test whether a `sessionToken` cookie **exists**, never whether it is valid. Any cookie with that name passes: the middleware treats the request as logged in (bypassing `RESTRICT_IP`), and `validateApiKey` accepts it in place of an API key, which the OpenAI-compatible chat completions use.                                                                                                                   | `middleware/createMiddlewareRequestContext.ts` (`isLoggedIn`), `utils/validateApiKey.ts`, `utils/handleChatCompletion.ts`                               |
| 3   | High     | A legacy `adminToken` cookie is compared with the raw `ADMIN_PASSWORD`, so the admin password itself works as a bearer credential.                                                                                                                                                                                                                                                                                                                | `utils/getCurrentUser.ts`                                                                                                                               |
| 4   | High     | Route handlers with no access check of their own. `GET /api/chat` calls the server's OpenAI key with any message from the query string. `/api/browser-test/*` drives the server's browser. They rely only on the middleware's IP and visibility rules, which finding 2 bypasses. With 146 `route.ts` files and no deny-by-default policy, others like them are likely (`/api/long-running-task` and `/api/long-streaming` are examples to check). | `app/api/chat/route.ts`, `app/api/browser-test/act`, `app/api/browser-test/screenshot`, `app/api/browser-test/scroll-facebook`                          |
| 5   | High     | Password sign-in, including the special `admin` user checked against `ADMIN_PASSWORD` in plain text. There is no rate limit on sign-in, no second factor and no passkey.                                                                                                                                                                                                                                                                          | `utils/authenticateUser.ts`, `app/api/auth/login/route.ts`, `loginAction` in `app/actions.ts`                                                           |
| 6   | High     | API tokens (`ptbk_…`) are stored in plain text, so a database read yields working credentials. They carry no scope or expiry.                                                                                                                                                                                                                                                                                                                     | `app/api/api-tokens/route.ts`, `middleware/createMiddlewareRequestContext/isRequestAuthorizedByApiToken.ts`, `utils/managementApi/managementApiAuth.ts` |
| 7   | High     | No CSRF protection anywhere. The session cookie sets no `SameSite`, and server actions and state-changing routes accept cross-site requests.                                                                                                                                                                                                                                                                                                      | `utils/session.ts`, `app/actions.ts`                                                                                                                    |
| 8   | Medium   | Permissive CORS: `Access-Control-Allow-Origin: *` answers every preflight, and the management API defaults to `*`.                                                                                                                                                                                                                                                                                                                                | `middleware/resolveAccessControlResponse.ts`, `utils/managementApi/managementApiCors.ts`                                                                |
| 9   | Medium   | The client IP comes from `X-Forwarded-For`, so IP allowlists and any per-IP limit can be spoofed when the server is reached directly.                                                                                                                                                                                                                                                                                                             | `middleware/createMiddlewareRequestContext/getRequestIp.ts`                                                                                             |
| 10  | Medium   | Inline scripts in the root layout: a theme bootstrap, and **admin-provided custom JavaScript from the database**, also served by `/api/custom-js` and `/api/embed.js`. A strict CSP with Trusted Types is impossible while they exist, and the custom JavaScript runs on the engine's origin.                                                                                                                                                     | `app/layout.tsx` (the two `dangerouslySetInnerHTML` script blocks), `app/api/custom-js`, `app/api/embed.js`                                             |
| 11  | Medium   | No security headers: no CSP, HSTS, `nosniff`, `Referrer-Policy` or `Permissions-Policy`. Only headless chat embeds get `frame-ancestors`.                                                                                                                                                                                                                                                                                                         | `middleware/applyEmbeddingHeader.ts`, `next.config.ts`                                                                                                  |
| 12  | Medium   | Wallet secrets (passwords, secrets and cookies of a user's external accounts) are stored in plain text.                                                                                                                                                                                                                                                                                                                                           | `database/migrations/2026-03-0010-user-wallet.sql` (`UserWallet`)                                                                                       |
| 13  | Medium   | Dynamic code execution in the engine: JavaScript execution tools that run code with `eval`.                                                                                                                                                                                                                                                                                                                                                       | `src/scripting/javascript/JavascriptEvalExecutionTools.ts` in the monorepo root (not under `apps/agents-server`)                                        |
| 14  | Low      | The Next.js app is the only server: no pre-auth gateway, and app router pages and server actions form an implicit RPC layer. That layer carried CVE-2025-29927, a middleware authorisation bypass.                                                                                                                                                                                                                                                | `middleware.ts`, `app/`                                                                                                                                 |

Model markdown is rendered with `dangerouslySetInnerHTML` after DOMPurify (`book-components/Chat/utils/renderMarkdown.ts` in the monorepo root). We found no problem there, but the strict CSP is still the backstop (Security hardening 5).

## What replaces it

In tunnel mode none of the code above may sit in front of the engine API or the UI. The engine-side kit says so without naming these findings ([implementation-plan.md](../engine-integration/implementation-plan.md#where-things-go-in-the-engine), "Replace, do not reuse").

| Findings   | Replacement                                                                                                                                                                                                                    | Covered in                                                                                                                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1, 2, 3, 7 | Server-side sessions with 128-bit random IDs in a `__Host-` cookie (`Secure`, `HttpOnly`, `SameSite=Strict`), idle and absolute timeouts, revocation within one request, Fetch Metadata and `Origin` checks before any handler | [gateway.md](../engine-integration/gateway.md#sessions), phase 6 of the [plan](../engine-integration/implementation-plan.md#phase-6-the-gateway); checks `engine-api.gateway.cross-site-refused`, `engine-api.me.*` |
| 4, 14      | The gateway as the only listener, with anonymous access limited to sign-in, setup and public agents; the app server on 127.0.0.1 only; one deny-by-default policy module                                                       | [gateway.md](../engine-integration/gateway.md#anonymous-access); check `engine-api.auth.unauthenticated-401`                                                                                                        |
| 5          | Passkeys only, with the setup secret for the owner's first passkey and step-up for sensitive actions; no password fallback                                                                                                     | [gateway.md](../engine-integration/gateway.md#step-up), the spec's [Pairing and identity](../spec/zero-trust-spec.md#pairing-and-identity)                                                                          |
| 6          | API tokens stored hashed, scoped by permissions, with an expiry, shown once (`CreateApiTokenResult`)                                                                                                                           | [engine-api.md](../engine-integration/engine-api.md#secrets-are-write-only)                                                                                                                                         |
| 8          | No CORS: the engine API is same-origin only                                                                                                                                                                                    | [gateway.md](../engine-integration/gateway.md#cross-site-protection)                                                                                                                                                |
| 9          | The client IP is the tunnel's `OPEN` frame address, never a header                                                                                                                                                             | [tunnel-client.md](../engine-integration/tunnel-client.md#frames)                                                                                                                                                   |
| 10, 11     | The engine origin serves only the gateway pages, `/api/v1` and our verified UI bundle, under `ENGINE_UI_CSP` with Trusted Types and the full header set; no custom JavaScript in tunnel mode                                   | [gateway.md](../engine-integration/gateway.md#security-headers), [ui-loader.md](../engine-integration/ui-loader.md)                                                                                                 |
| 12         | Secrets encrypted at rest and write-only through the API                                                                                                                                                                       | [engine-api.md](../engine-integration/engine-api.md#secrets-are-write-only), the spec's [Engine security baseline](../spec/zero-trust-spec.md#engine-security-baseline)                                             |
| 13         | No `eval`, `new Function` or `vm` in anything the gateway or the API reaches, enforced by a lint rule; tool calls resolved through an allowlist                                                                                | [AGENT_BRIEF.md](../engine-integration/AGENT_BRIEF.md) rule 3, Security hardening 6                                                                                                                                 |

## What this page does not do

It is not a pentest. It reads one commit, and anything the engine changed since may differ. The spec's gate to v0 (an internal break-it attempt, a cryptography review and a pentest before general availability) still applies to the new engine code.
