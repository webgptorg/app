# Engine checklist

Every requirement in this guide in one table, for the engine team's tracker. Copy it, add your own status column, and keep the IDs. [implementation-plan.md](implementation-plan.md) orders these rows into build phases.

- **Spec:** the section of the [spec](../spec/zero-trust-spec.md) that says why. "If" means [Interfaces (draft)](../spec/zero-trust-spec.md#interfaces-draft).
- **Contract:** the export to build against, in `@ptbk/protocol` (P) or `@ptbk/engine-api` (A).
- **Check:** the conformance check ID. IDs marked "registered, skip" exist in `packages/conformance` but report `skip` (`not-implemented`) until their suite exists; "—" means no check is planned yet, so the golden vectors or the contract tests are the proof.
- **Reference:** where the mock engine does it: merged, or pending the named task.

Every conformance check ID that exists in `packages/conformance` must appear in this table; `bun run check` fails otherwise.
