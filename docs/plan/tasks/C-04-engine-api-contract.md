# C-04. Engine API contract v1 and typed client

- **Lane:** Contracts · **Module:** `packages/engine-api` · **Milestone:** M2
- **Depends on:** —
- **Status:** todo
- **Spec:** Security hardening (preamble, items 1, 5, 7, 8), Transparency and verifiability (3. Self-checks), Engine security baseline, Enterprise-ready engine architecture (API, Authorisation, Audit), Interfaces (draft) 6; ADRs: [0003](../../adr/0003-ui-as-signed-bundle.md), [0004](../../adr/0004-mock-engine-and-conformance.md)

## Goal

`@ptbk/engine-api` defines the engine's HTTP API for the UI as strict zod schemas plus a route table, generates an OpenAPI 3.1 document from them, and ships an `EngineApiClient` port with a fetch-based implementation.

## Context

engine-ui (U-01…U-07) talks only to this API; the mock engine (M-04) serves it now and the real engine later. The owner sees and controls everything (Security hardening preamble); the only things never readable are secret values. Sign-in, sessions, passkeys at sign-in, CSRF (Fetch Metadata) and step-up are enforced by the open engine gateway: this API assumes a `__Host-` HttpOnly session cookie and same-origin requests. Feature inventory comes from the predecessor (agents-server): agents from "book" source, folders, history and diagnostics, visibility, delete/restore, chats, members, API tokens, settings, secrets, files. Same portability rules as `protocol`; it cannot import `@ptbk/protocol`, so it defines its own branded types and has no dependency on C-01.

Decided: the contract is ready for organisations with several members and roles from day one. v0 has a single owner and no multi-user features, but nothing may assume one user: the UI decides by **permission**, never by role name, every mutating route declares the permission it needs, and the audit log records which member did what.

## Scope

- `src/common.ts`: branded IDs (`AgentId`, `FolderId`, `RevisionId`, `ChatId`, `MessageId`, `MemberId`, `ApiTokenId`, `SecretId`, `FileId`, `AuditEntryId`, `PasskeyId`, `SessionId`; opaque `[A-Za-z0-9_-]{1,64}`), its own `Timestamp` (RFC 3339 UTC), `Hostname` and `SemVer` schemas (same rules as C-01's, defined independently), `Page<T> { items, nextCursor: string | null }`, `PageQuery { cursor?, limit? (1–100, default 50) }`, `ProblemDetails` (RFC 9457: `type, title, status, detail?, instance?, code`, optional `errors: [{ path, message }]` for validation).
- Resource schemas and routes under `/api/v1` in one file each (`src/agents.ts`, `chats.ts`, …):
  - **Me:** `GET /me` → `{ memberId, orgId, displayName, role: Role, permissions: Permission[] }`.
  - **Engine info:** `GET /engine` → `{ name, hostname, dashboardUrl | null, mode: 'tunnel' | 'direct' | 'local' }` (`dashboardUrl` is `null` when the engine is not linked, e.g. local mode). `/me` and `/engine` are the only routes any signed-in member may call without a specific permission.
  - **Permissions** (`src/permissions.ts`): `Role = 'owner' | 'admin' | 'member' | 'viewer'`; `Permission`, a closed union of capability strings: `agents.read`, `agents.write`, `agents.delete`, `agents.run` (draft), `chats.read`, `chats.write`, `files.read`, `files.write`, `secrets.read` (metadata only; values are never readable), `secrets.manage`, `members.read`, `members.manage` (draft; also covers revoking another member's passkeys), `api-tokens.manage`, `settings.manage` (includes the update policy), `security.read`, `audit.read`. The role-to-permission mapping is engine policy, not contract; the contract only guarantees that `owner` holds every permission.
  - **Agents:** `GET /agents?q&folderId&visibility&status&deleted&sort&cursor&limit` (`sort`: `name` | `updatedAt` | `createdAt`, each with `-` for descending; `status` filters by run state); `POST /agents { source, folderId?, visibility? }`; `GET|PATCH /agents/{id}` (`visibility`, `folderId`); `DELETE /agents/{id}` (soft); `POST /agents/{id}/restore`. `Agent { id, permanentId, name, profile { fullname, description, avatarUrl | null, color | null, initialMessage | null }, visibility: 'public' | 'private' | 'unlisted', folderId | null, currentRevisionId, createdAt, updatedAt, deletedAt | null }`.
  - **Source:** `GET /agents/{id}/source`; `PUT /agents/{id}/source { source, baseRevisionId }` (409 `revision-conflict`); `GET /agents/{id}/revisions` (paged); `GET /agents/{id}/revisions/{revisionId}`; `POST /agents/validate { source }` → `Diagnostic[] { severity: 'error' | 'warning' | 'info', code, message, range { startLine, startColumn, endLine, endColumn } }`. `POST /agents` and `PUT /agents/{id}/source` with a book that has an `error` diagnostic return 422 problem+json with code `invalid-book` and the extension `diagnostics: Diagnostic[]`; nothing is stored.
  - **Run control (draft):** `GET /agents/{id}/status` → `{ state: 'idle' | 'running' | 'stopped' | 'error', since }`; `POST /agents/{id}/start`, `POST /agents/{id}/stop`.
  - **Engine events:** `GET /events` as SSE, `EngineEvent = { type: 'agent.status', agentId, state, since } | { type: 'agent.changed', agentId } | { type: 'chat.changed', chatId }`, filtered by the member's permissions, resumable with `Last-Event-ID`, so the UI updates lists without polling.
  - **Folders:** list, create, rename, delete (409 if not empty).
  - **Chats:** `GET|POST /agents/{id}/chats`; `GET /chats/{chatId}`; `GET /chats/{chatId}/messages` (paged, newest first); `POST /chats/{chatId}/messages { content }` → 202 `{ userMessage, replyMessageId }`; `GET /chats/{chatId}/messages/{messageId}/stream` as SSE; `POST /chats/{chatId}/messages/{messageId}/cancel` (`chats.write`) stops a reply in progress, after which the stream ends with `failed` and problem code `cancelled` (idempotent; 409 `reply-finished` once the reply has completed).
  - **Members:** `Member { id, displayName, role, status: 'active' | 'invited' | 'disabled', createdAt, lastSeenAt | null }`; `GET /members` (paged) and `GET /members/{id}` in v0. Designed now, marked `draft` (v1): `PATCH /members/{id} { role }`, `DELETE /members/{id}`, `GET|POST /invites` (`{ role, expiresAt }` → `{ invite, inviteUrl }`, URL returned once), `DELETE /invites/{id}`.
  - **API tokens** (list, create returning the token once, revoke), **settings** (`GET|PATCH /settings`; `GET /settings` includes `updatePolicy { policy, pinnedVersion | null }`; `PUT /settings/update-policy { policy: 'auto' | 'manual' | 'pinned', pinnedVersion? }` with permission `settings.manage` and `stepUp`; `pinnedVersion` required exactly when `policy` is `pinned`), **passkeys and sessions** (list, revoke).
  - **Secrets** (reads need `secrets.read`, writes `secrets.manage`): `SecretMetadata { id, name, scope: { kind: 'engine' } | { kind: 'agent', agentId }, status: 'active' | 'revoked', createdAt, updatedAt, lastUsedAt | null }`; `GET /secrets?q&scope&status&sort&cursor&limit` (`sort`: `name` | `createdAt` | `lastUsedAt`, each with `-` for descending; paged like every list); `POST /secrets { name, scope, value }`; `PUT /secrets/{id}/value { value }`; `POST /secrets/{id}/revoke`; `DELETE /secrets/{id}`. No response schema has a value field.
  - **Files:** list (paged), upload (`multipart/form-data`), download, delete.
  - **Security panel:** `GET /security` → `{ engine { version, releaseLogIndex | null }, update { status: 'none' | 'available' | 'pending' | 'installing', policy, pinnedVersion | null, availableVersion | null, eligibleAt | null }, ui { version, bundleSha256, releaseLogIndex | null }, tls { certificateSha256, notAfter, lastCtCheck { at, result: 'ok' | 'unexpected-certificate' | 'failed' } | null }, relays: [{ hostname, status: 'connected' | 'connecting' | 'disconnected', since }], hostnames: [{ hostname, kind: 'default' | 'custom' }], lastHeartbeat { sentAt, body: string } | null, outboundDestinations: string[] }`. `body` is the exact bytes sent, as text.
  - **Audit:** `GET /audit?memberId&action&targetKind&targetId&outcome&from&to&cursor&limit` (`outcome`: `success` | `denied` | `failed`) → `AuditEntry { id, seq, at, actor: { kind: 'member', memberId } | { kind: 'api-token', apiTokenId, memberId } | { kind: 'system' }, action (closed union of dotted names, e.g. `agent.create`, `secret.replace`), target { kind, id } | null, outcome: 'success' | 'denied' | 'failed', client: { ip, userAgent } | null, hash, prevHash }`. `client` comes from the tunnel's `OPEN` frame (IP) and the request (`User-Agent`, truncated to 512 chars); `null` for system actions. `GET /audit/verify` (`audit.read`) → `{ status: 'intact' | 'broken', checkedEntries, lastSeq | null, firstBrokenSeq | null, checkedAt }`: the engine re-walks the whole hash chain, so the owner can confirm nothing was removed or edited.
  - Owned resources (agents, chats, secrets, files, API tokens) carry `createdBy: MemberId`; no route is a "my" shortcut except `/me`.
- `src/routes.ts`: `ENGINE_API_ROUTES`, a typed table of `{ id, method, path, permission: Permission | null, params?, query?, body?, responses, stepUp?: true, draft?: true }` (`null` only for `/me` and `/engine`); the single source for the client, the OpenAPI document and the conformance suite.
- `src/openapi.ts`: `buildOpenApiDocument()` using zod 4's `z.toJSONSchema()`; `openapi.json` committed, with a test that fails when it is stale.
- `src/client.ts`: `EngineApiClient` interface (grouped: `agents`, `chats`, `secrets`, …; every method takes an `AbortSignal`) returning `EngineApiResponse<T> = { kind: 'ok', data: T } | { kind: 'problem', problem: ProblemDetails }`; `createFetchEngineApiClient({ baseUrl, fetch, timeoutMs })` with `credentials: 'same-origin'`. Network failure and timeouts throw; a response that fails its schema throws `EngineApiContractError` (a bug).
- `src/constants.ts`: `ENGINE_API_PREFIX = '/api/v1'`; `ENGINE_API_VERSION` (SemVer of this contract, starting at `1.0.0`; additive changes bump the minor, the UI bundle manifest's `engineApi` range refers to it, C-06/X-03); the gateway paths `SIGN_IN_PATH = '/auth/sign-in'`, `SIGN_OUT_PATH = '/auth/sign-out'`, `STEP_UP_PATH = '/auth/step-up'`; `ENGINE_RESERVED_PATHS` (`/api/`, `/auth/`, `/setup`, `/.well-known/`), which the UI loader's SPA fallback must never shadow; and `ENGINE_UI_CSP`, the exact header the engine sends with the UI. This package is the single source of the string: [U-01](U-01-engine-ui-scaffold.md) imports it and proves the bundle survives it, M-05 and conformance send or check the same export: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-src 'none'; frame-ancestors 'none'; require-trusted-types-for 'script'; trusted-types ptbk-html`.
- `src/in-memory-client.ts`: `createInMemoryEngineApiClient({ seed?, clock?, member? })` (member and permissions configurable, so UI tests cover a member without a permission) implementing `EngineApiClient` on plain maps with the same observable rules (strict validation of inputs, cursor paging, soft delete, revision conflicts, secrets without values, scripted streamed replies). It exports `IN_MEMORY_CLIENT_MARKER` so U-01 can prove it is absent from production builds.
- `src/sse.ts`: portable SSE parser over a `ReadableStream<Uint8Array>`; `ReplyStreamEvent = { type: 'delta', seq, text } | { type: 'completed', message } | { type: 'failed', problem }`; resume with `Last-Event-ID` (event id = `seq`).

## Out of scope

- Gateway, sign-in, passkey registration, setup secret (open engine). Serving the API over HTTP with seeded faker data (M-04). Implementing invites and role changes (v1; only their shapes are defined here).

## Design notes

- OpenAPI: zod 4 `z.toJSONSchema()` plus a small hand-written builder over the route table. Chosen over `@hono/zod-openapi` because the contract must not tie the engine to Hono (spec allows Hono or Fastify) and should add no dependency beyond zod.
- Requests: request schemas are strict too, so the engine rejects unknown fields with 400 `validation-failed`. Anonymous calls get 401 `unauthenticated`; a member without the route's permission gets 403 problem+json with code `forbidden` and the extension `requiredPermission`; routes flagged `stepUp` may get 401 `step-up-required` (the spec requires it for the update policy and risky actions; flag at least update policy, API token create and passkey revoke, and confirm the rest with the engine team). Problem `code` values are a closed enum exported from `src/problem-codes.ts` (including `invalid-book`, `cancelled`, `reply-finished`).
- Cursors are opaque strings; a malformed or expired cursor is 400 `invalid-cursor`. Order is stable under inserts.

## Acceptance criteria

- [ ] Every route has request and response schemas; a test asserts no response schema anywhere contains a `value`, `secret` or `token` field except `POST /api-tokens`.
- [ ] Tests: each schema rejects unknown fields; SSE parser property test (arbitrary chunk splits of a valid stream yield the same events; never throws on arbitrary bytes); client tests with a fake `fetch` cover ok, problem+json, schema mismatch, timeout and abort; one shared client test suite runs against the in-memory client and the fetch client wired to an in-process handler built from the in-memory client.
- [ ] A route-table test asserts every route except `/me` and `/engine` declares a permission, every mutating route declares a non-`.read` permission, and the OpenAPI document lists it per operation (`x-required-permission`) together with the 403 response.
- [ ] `openapi.json` validates as OpenAPI 3.1 and is regenerated by `bun run --filter @ptbk/engine-api openapi`.
- [ ] `bun run check` passes.
- [ ] **Status** line above set to `done (#<PR>)`.

## Risks and open points

- Base path `/api/v1`, `permanentId` semantics (assumed: stable across renames, used in public URLs), whether `profile` is derived from the book source (assumed read-only) and the file upload format need confirming with the engine team.
- The capability list is a first cut; adding a permission later is non-breaking, renaming one is breaking. Review it with the engine team before E-01.
- Run-control endpoints are marked `draft`: what start/stop means for Claude Code and Codex agents is not specified.
- Public agents (anonymous chat) are a gateway exception and not part of this authenticated API; open spec question.
