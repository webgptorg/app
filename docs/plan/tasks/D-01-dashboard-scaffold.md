# D-01. Dashboard scaffold: TanStack Start on Workers, D1, environments

- **Lane:** D · **Module:** `apps/dashboard` · **Milestone:** M3
- **Depends on:** — · **Unblocks:** D-02, I-02
- **Status:** todo
- **Spec:** Hosting and stack; One address for users; What our platform can and cannot do; Enterprise-ready engine architecture; ADRs: [0001](../../adr/0001-bun-workspaces-monorepo.md), [0005](../../adr/0005-modular-architecture.md), [0006](../../adr/) (Organizations, members and roles from day one)

## Goal

`apps/dashboard` builds, runs locally and tests on Cloudflare Workers with TanStack Start and D1, in three environments (dev, staging, production), with the ports-and-adapters skeleton, the organization tenancy model with one `Authorizer` policy port, and English and Czech i18n that every later D task builds on.

## Context

app.ptbk.io is the entry point: account, engine list, billing, status. It links to engines and never loads their data or stores their content (AGENTS.md rules 2 and 3). It also serves three machine APIs (registration, registry, heartbeat) that later tasks add. Per ADR 0006, an `Organization` owns engines and billing, users join through a `Membership` with a role, and all authorization goes through one policy port. v0 only creates personal organizations with one `owner`, but the model must take multi-user orgs later without moving ownership. The team prefers Cloudflare over Vercel.

## Scope

- TanStack Start 1.169, React 19, Vite with `@cloudflare/vite-plugin`; wrangler 4.15x (newest patch at least 7 days old) as a dev dependency.
- `wrangler.jsonc`: `main: "src/worker.ts"`, `compatibility_flags: ["nodejs_compat"]`, D1 binding `DB`, `migrations_dir: "migrations"`, `observability` on. Top level is dev (local only); `env.staging` and `env.production` have their own D1 database, vars and routes as placeholders (`<staging-d1-id>`, `app.staging.<placeholder>`); I-02 fills them in.
- `src/worker.ts` (default export allowed): `/v1/*`, `/internal/*`, `/webhooks/*` go to a framework-free API router in `src/app/api/router.ts`; everything else to the TanStack Start handler. Later tasks add the Durable Object export and the `scheduled` handler here.
- `migrations/0001_tenancy.sql`:
  - `organizations(id TEXT PK, kind TEXT NOT NULL CHECK (kind IN ('personal','team')), name TEXT, created_at INTEGER NOT NULL)`
  - `users(id TEXT PK, email TEXT UNIQUE NOT NULL, email_verified_at INTEGER, locale TEXT NOT NULL DEFAULT 'en', platform_role TEXT NOT NULL DEFAULT 'none', recovered_at INTEGER, created_at INTEGER NOT NULL)`
  - `memberships(org_id TEXT NOT NULL REFERENCES organizations, user_id TEXT NOT NULL REFERENCES users, role TEXT NOT NULL, created_at INTEGER NOT NULL, PRIMARY KEY (org_id, user_id))`. No CHECK on `role` (SQLite cannot alter one); the zod schema in the adapter allows `'owner'` now and grows later.
- Branded IDs `OrgId`, `UserId`; `OrgRole` and `PlatformRole` unions.
- `Authorizer` port in `src/domain/authz/`: `can(actor, action, resource) → { kind: 'allowed' } | { kind: 'denied', reason: 'not-member' | 'role' | 'recovery-cooldown' | 'platform-admin-only' }`, where `actor = { userId, orgId, orgRole, platformRole, recoveredAt }` and `resource = { kind: 'org', orgId } | { kind: 'engine', orgId, engineId } | { kind: 'platform' }`. One policy table maps each action to allowed org roles, a `platformAdminOnly` flag and a `sensitive` flag; sensitive actions are denied with `recovery-cooldown` for 72 h after `recoveredAt` (D-02 sets it). Start with `org.read`; each later task adds its actions to the table. The policy takes a `Clock`.
- Config: `src/app/config.ts` parses bindings with a strict zod schema into a frozen `DashboardConfig` (`environment`, `dashboardOrigin`, `engineDomain`, `relays`). Nothing else reads `env`.
- Ports `Clock`, `Random`, `Logger` with system adapters and in-memory fakes.
- i18n with Paraglide JS 2, the same library engine-ui uses (messages compiled at build time, typed message functions, no eval): catalogues `messages/en.json` and `messages/cs.json`, compiled output generated by the Vite plugin and not committed. Locale resolution: user's `locale`, then a `ptbk_locale` cookie, then `Accept-Language`, then `en`, wired through Paraglide's server middleware for SSR. `<html lang>` follows it; a language switcher sits in the shell. Dates and numbers through `Intl`. A lint rule forbids literal user-facing strings in `src/routes/**` and components.
- `GET /v1/health` → `{ "ok": true, "environment": "<env>" }`, `Cache-Control: no-store`.
- Security headers on HTML: CSP `default-src 'self'; connect-src 'self'; frame-src 'none'; frame-ancestors 'none'; object-src 'none'; base-uri 'none'` with per-request nonces for TanStack Start's hydration scripts, HSTS, `Referrer-Policy: no-referrer`, `nosniff`, COOP `same-origin`. `connect-src 'self'` makes "the dashboard never fetches engine data" browser-enforced.
- Tests: Vitest projects `unit` (Node pool, domain with fakes) and `workers` (`@cloudflare/vitest-pool-workers` 0.23, migrations applied with `readD1Migrations`/`applyD1Migrations`).
- Local and containerized dev with TLS, because passkeys need a secure context on a real hostname and X-05 runs the dashboard in its compose stack: `apps/dashboard/Dockerfile.dev` runs `wrangler dev` (local D1, local Durable Objects) serving HTTPS with a certificate and key passed in by path (the e2e dev CA from X-01/M-02, or a locally generated one), on a configurable hostname such as `app.ptbk.test`. `dashboardOrigin` and the WebAuthn rpID follow that hostname through config.
- Adapter selection in config: `adapters: { email: 'cloudflare' | 'fake', billing: 'stripe' | 'fake', rateLimit: 'workers' | 'memory' }`. The config schema rejects any `fake` or `memory` value unless `environment` is `dev`, so a staging or production deploy cannot run on fakes.
- Scripts: `dev`, `dev:https`, `build`, `typecheck`, `test`, `cf-typegen` (output committed). No deploy script (I-03). README updated.

## Out of scope

- Signup, passkeys, sessions, recovery, `EmailSender` (D-02); engines (D-03); Durable Objects (D-05); Stripe (D-07); team orgs and invites (later).
- Real Cloudflare resources and DNS (I-02); deploy workflows (I-03).

## Design notes

- Layout: `src/domain/`, `src/adapters/`, `src/app/`, `src/routes/` (file routes use `export const Route`), `src/i18n/`, `src/worker.ts`. `src/routeTree.gen.ts` is excluded from lint and format.
- Rule for every later task: org-owned stores take `orgId` as the first argument and put it in every `WHERE`; routes call `Authorizer.can` and never compare role names. Each org-scoped adapter test includes "org B cannot read or change org A's rows".
- Keep the API router importable without TanStack Start; if the full Start entry is awkward in the pool, add `test/worker-entry.ts` wiring only the API router.
- Machine routes ignore cookies and return `{ "error": "<code>" }`, never stack traces or input echoes.
- `src/app/schema-allowlist.test.ts` lists every table and column after all migrations against a checked-in allowlist, so a new column is a visible review point for "no engine content".

## Acceptance criteria

- [ ] `bun run --filter @ptbk/dashboard dev` serves the home page and `/v1/health` with a local D1; `build` works for `CLOUDFLARE_ENV=staging` and `production`.
- [ ] Workers tests: health 200 with `no-store`; HTML has the CSP with a nonce and no `unsafe-inline` or `unsafe-eval`; unknown `/v1/*` → 404 JSON. Unit: config fails closed on a missing or unknown var.
- [ ] Authorizer unit tests: owner allowed on own org; non-member denied `not-member`; platform-only action denied for a normal user; sensitive action denied `recovery-cooldown` at 71 h 59 min after recovery and allowed at 72 h.
- [ ] i18n: a test fails if `messages/en.json` and `messages/cs.json` do not have exactly the same keys or any value is empty; the home page renders in Czech with `Accept-Language: cs`; the literal-string lint rule is active.
- [ ] The dev container starts, serves `https://<dev hostname>/v1/health` with the supplied certificate, and config refuses `adapters.billing = 'fake'` with `environment = 'staging'` (unit test).
- [ ] Schema allowlist test passes; `domain/` has no platform or adapter imports.
- [ ] `bun run check` passes.
- [ ] **Status** line above set to `done (#<PR>)`.

## Risks and open points

- TanStack Start's nonce support must cover every inline script it emits; if not, stop and flag rather than allow `unsafe-inline`.
- Paraglide JS 2 must be at least 7 days old at the pinned version and its Vite plugin must work with `@cloudflare/vite-plugin`; if they conflict, flag it rather than switching library alone.
- Staging hostname and Cloudflare account layout are decided in I-02.
- If ADR 0006 and this brief differ, follow the ADR and note it in the PR.
