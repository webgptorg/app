# Apply checklist

The code for every task lands before the cloud accounts exist ([local-first](README.md#current-priority-local-first)). What is left needs a credential, an account, a domain or a person: these are the **Apply** steps. Each task below lists its own under "Apply (needs credentials)" in its brief; this page collects them and every credential they need, in the order to run them.

Each Apply step is a PR or a runbook run with `Refs: <task>`. Secrets go into the place named below (a password manager, a GitHub environment secret, `wrangler secret put` or a host credential file), never into the repo, a PR, a log or this page.

For staging, [staging-runbook.md](../staging-runbook.md) runs the steps below in order by hand, without CI: accounts, tokens, secrets, placeholders, both stacks, the dashboard, email, the relay host and a linked mock engine.

## Google Web Risk (I-08)

The `abuse-feeds` job needs one Google Cloud API key per environment (staging and production may share a project; separate keys keep a revocation local). Done with I-05's step 8:

1. A Google Cloud project for the platform with billing enabled. `threatLists.computeDiff` is free; `hashes.search` is billed at $50 per 1,000 calls with no free tier, and the adapter makes at most 50 per run ([I-08](tasks/I-08-web-risk-abuse-feed.md), Risks). Set a budget alert on the project, e.g. $50 a month, to the ops mailbox.
2. Enable the API: `gcloud services enable webrisk.googleapis.com --project <project>`.
3. Create the key with an API restriction to Web Risk only: `gcloud services api-keys create --project <project> --display-name ptbk-<env>-web-risk --api-target=service=webrisk.googleapis.com`. Workers have no fixed egress address, so no IP application restriction; the API restriction is what limits a leaked key.
4. Store it in the password manager, then `wrangler secret put WEB_RISK_API_KEY --env <env>` in `apps/dashboard`. Never paste it into a PR, an issue, a log or this page.
5. After the next 15-minute run, the Cron Trigger log shows `abuse-feeds` succeeded and no `web-risk.diff-failed`; this also confirms that Web Risk accepts the key in the `X-Goog-Api-Key` header. To rotate, create a new key, put it, wait for one good run, then delete the old one (`gcloud services api-keys delete`).
